# Compose versus Kubernetes
Compose uses a private bridge network and named volumes. Docker restart policies can restart a failed container, but Compose does not provide a StatefulSet controller or cluster scheduling. Kubernetes reconciles desired replica count, creates replacement pods with stable names and reattaches PVCs. The headless Service provides per-pod DNS. Kubernetes requires a cluster, storage provisioner, Secret management and more operational configuration. Both deployments use three voting data-bearing members and a shared keyfile; neither is a fully hardened production installation. The Kubernetes test records pod UID and PVC UID before and after deletion and checks the same majority-written document on all members. Replication can also recover data, so retaining a PVC and verifying a document demonstrate persistence and recovery together, not proof that no replication occurred.

The assignment's proposed emptyDir shared across pods is not possible: emptyDir is pod-local. One generated Kubernetes Secret supplies the same key to each init container, which copies it into a pod-local emptyDir with MongoDB ownership and mode 0400.
