# Lab 17 — AI-native MongoDB: Vector Search and RAG
Independent Docker Compose project. No frontend; Lab 7 remains separate. Run START-WINDOWS.bat, RUN-LABS.bat, PUBLISH-DOCKER.bat, RUN-PUBLISHED.bat in that order. Docker Hub login should already be valid (otherwise `docker login`). First run downloads CPU embedding and Ollama model weights; Internet required. Keep other labs stopped; allow approximately 8 GB Docker RAM and ample disk (10+ GB free recommended). All three services can be stopped using the Compose group; volumes retain data/models. No host ports exposed.

## 17.1
Five original educational CTI documents, 100-word windows with 20-word overlap (short final windows), real all-MiniLM-L6-v2 embeddings (384 dimensions), MongoDB Atlas Local native vector index, $vectorSearch with 20 candidates and top 3, real local Qwen2.5 generation via Ollama. The prompt includes the previous five user/assistant exchanges (10 messages), not just five messages, following the activity wording. Six explicitly synthetic memory fixtures test truncation; three actual LLM calls test generation, follow-up and user isolation. Sources and exact prompts are recorded; generated answers are not automatically certified factual. Run `docker compose exec app python ask.py --user manual-demo "What is ransomware?"` after RUN-LABS for a manual question; repeat with same user for memory. The default small model is resource-conscious; override LLM_MODEL in .env for a larger Ollama model.

## 17.2
5,000 unique, reproducible synthetic natural-language sentences (not Wikipedia extracts), real 384-dimensional embeddings, MongoDB inserts in batches of 500. All FAISS indexes use vectors read back from the same MongoDB benchmark collection. Native MongoDB HNSW is measured at 50/100/200/400 candidates; controlled FAISS HNSW varies M=8/16/32, efConstruction=32/64/128/256 and efSearch=32/64/128. FAISS IVF varies nlist=50/100/200 and nprobe=10/50/100/nlist (clamped and deduplicated). Each configuration executes the same 100 random document vectors, retrieving top 20, against NumPy exact cosine ground truth. Build and latency measured by perf_counter; recall is intersection size /20. Native index build includes asynchronous readiness and polling. FAISS builds are reused for search-parameter sweeps. Native latency includes server/network/BSON overhead; FAISS is in-process. Results are not interchangeable production benchmarks. Each run creates a unique benchmark collection to measure fresh index build; old runs remain for evidence (remove manually only if desired). CSV/JSON, query-level results, PNG/SVG latency-recall frontier, recommendations, and RAG JSON are saved under evidence/ (overwritten on repeat runs).

## Assignment deviations and references
Atlas Local is a genuine MongoDB Vector Search development deployment, not hosted Atlas. To use hosted Atlas instead, create .env with MONGO_URI=your Atlas URI (never commit credentials); use a dedicated cluster/database and appropriate permissions. The local mongo service still starts but is unused by the application in that mode. Native MongoDB documents HNSW and flat, not IVF; FAISS is used for both controlled sweeps, with a native HNSW baseline. This does not fulfill the literal native IVF requirement; obtain instructor approval if required. Synthetic benchmark corpus substitutes for the sample Wikipedia corpus to make the experiment reproducible. Instructor GitHub chapter could not be retrieved; the visible screenshots are the assignment basis. No paid API key needed.
